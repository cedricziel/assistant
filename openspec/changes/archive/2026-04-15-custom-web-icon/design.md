## Context

The Flutter web build outputs to `app/build/web/`, which is then embedded into the Rust binary via `rust-embed`. The PWA manifest at `app/web/manifest.json` references four icon files in `app/web/icons/` (192×192, 512×512, and maskable variants) plus a `favicon.png`. Currently these are Flutter's default template icons (the blue Flutter logo).

The macOS app already has a proper 1024×1024 source icon at `app/macos/Runner/Assets.xcassets/AppIcon.appiconset/app_icon_1024.png`. This is the canonical source of truth for the app's visual identity.

## Goals / Non-Goals

**Goals:**

- Replace all four PWA icon PNGs and the favicon with versions derived from the actual app icon
- Update `manifest.json` brand colors to match the app's palette
- Ensure the icons meet PWA installability requirements (correct sizes, maskable safe zone)

**Non-Goals:**

- Changing the app icon on macOS/iOS (those are already correct)
- Generating icons programmatically at build time (static replacements are sufficient)
- Theming or dark-mode icon variants

## Decisions

### Decision: Use the macOS 1024×1024 source asset as the origin

The macOS `app_icon_1024.png` is already in the repo and represents the canonical app icon. Resizing from 1024×1024 to 192×192 and 512×512 produces clean output without needing to introduce external tooling into the build pipeline.

**Alternative considered:** Using a separate SVG source — rejected because no SVG exists yet; deriving from the existing PNG avoids creating new assets.

### Decision: Generate maskable icons with padding (safe zone)

PWA maskable icons must keep content within the inner 80% safe zone so OS mask shapes (circles, squircles) don't clip the logo. The maskable variants will use the icon on a solid background with sufficient padding.

**Alternative considered:** Using the same PNG for both regular and maskable — rejected because without padding, logos get clipped on Android and iOS.

### Decision: Static PNG files checked into `app/web/icons/`

Icons are replaced as static files, not generated by the Flutter build or a CI step. This keeps the build simple (no ImageMagick dependency in CI) and is consistent with how Flutter's template initializes web icons.

**Alternative considered:** Adding a `make generate-icons` target that runs ImageMagick — reasonable for future automation but over-engineered for a one-time asset replacement.

### Decision: Update manifest colors to match brand

`background_color` and `theme_color` in `manifest.json` currently use Flutter's default `#0175C2`. These should reflect the actual app brand to improve the installed PWA splash screen and browser toolbar appearance.

## Risks / Trade-offs

- **Cached icons on existing installs** → Users who already installed the PWA may see the old icon until the service worker refreshes. No mitigation needed; this is standard PWA behavior.
- **Icon quality at small sizes** → Resizing from 1024×1024 PNG may produce soft edges at 192×192 without sharpening. The icon should be reviewed at target sizes before merging.
- **Maskable safe-zone compliance** → If the logo is close to edges in the source asset, padding may make it appear very small in the maskable variant. Verify on Android home screen.

## Migration Plan

1. Export/resize `app_icon_1024.png` → `Icon-192.png`, `Icon-512.png`, `Icon-maskable-192.png`, `Icon-maskable-512.png`, `favicon.png`
2. Place files in `app/web/icons/` and `app/web/` respectively (overwrite existing)
3. Update `manifest.json` colors
4. Run `flutter build web` locally to verify the icons appear in `build/web/`
5. Merge — no server-side migration or database change required

**Rollback:** Revert the PNG files and `manifest.json` via `git revert`.
